# GoalFlow 架构文档

## 设计目标

GoalFlow 的核心设计目标是解决 AI Agent 在长链路软件开发中的**目标漂移**和**半途而废**问题。

## 核心机制

### 1. 状态机驱动

六阶段状态机确保流程清晰可控：
- 每个阶段有明确的进入和离开条件
- 离开条件强制检查任务完成度
- 支持回退到任意阶段

### 2. 需求锚定

PRD（产品需求文档）作为不可变锚点：
- 一经生成，全链路只读引用
- 每阶段产出必须与 PRD 做一致性校验
- Self-Check Agent 独立评分，覆盖率 < 90% 强制打回

### 3. 原子任务与 DoD

Planning Agent 将需求拆分到不可再分：
- 每个任务有明确的完成定义（DoD）
- 任务状态由客观机制（测试通过、文件存在等）驱动
- 未完成的任务阻塞状态流转

### 4. 预算与升级

防止死循环和轻易放弃：
- 每个任务最多 N 次尝试
- 耗尽后触发 Escalation：重构方案或人工介入
- 不允许 Agent 自行跳过任务

## 扩展点

- **Agent 插件**：实现 BaseAgent 接口即可接入工作流
- **LLM 提供商**：通过 LLMClient 统一接口，支持任意模型
- **存储后端**：SessionManager 和 MemoryStore 可替换为其他实现
- **事件处理器**：通过 EventBus 订阅任意事件类型
